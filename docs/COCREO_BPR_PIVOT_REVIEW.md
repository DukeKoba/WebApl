# Cocreo「Claude Code × BPR」転換の検証

作成日: 2026-08-04
検証方法: 事業モデルアナリスト・保険代理店の購買意思決定者（6名代理店経営者A / 40名代理店役員D / 保険会社の代理店支援担当E）・競合市場アナリスト・デリバリー責任者の4視点で2周の相互批評を行い、対立点を裁定した
制約: 実行環境のネットワークポリシーにより cocreo.jp / x.com / App Store に到達できない。cocreo.jp の内容は git履歴（コミット `1b66888` で削除された `CocreoLanding.jsx`）から復元したものであり、現在の実サイトと差分がある可能性がある

---

## 0. 結論（先に4行）

1. **これは事業転換ではない。** cocreo.jp は既に「Cocreo Studio：受託開発30万円〜／AI統合（Claude/GPT）対応」を掲げている。検証すべき問いは「転換できるか」ではなく**「既に掲げているのに、なぜ1件も受注できていないのか」**。
2. **受注できない最大の原因は、販路でも価格でもない。** 主力デモ2本に中身がなく、それが買い手全員にとって取引中止の水準にある（§2）。**これが解消するまで他の議論に意味がないというのが買い手3名の一致した見解。**
3. **事業として成立する組み合わせは1つだけ存在する。** 「40名級の乗合代理店 × バラバラな様式・データを1本に統合する仕事 × 顧客データを預からない設計」。それ以外は人日単価が赤字になる（§5）。
4. **「Claude Code × BPR」という旗印は使えない。** 既にコモディティ化しており、かつ短縮率の実測（プロジェクト全体で25〜35%）がLPの主張と矛盾する。売るべきは道具ではなく**要件定義の質**（§6）。

## 2. 【最優先】主力デモに中身がない — 買い手全員が取引中止と判定

### 事実（コードで検証済み）

- `client/src/lib/cocreo/cases.js`（AIコンサル）と `client/src/lib/cocreo/subsidyGenerator.js`（補助金申請書AI）の**API呼び出し数はいずれも0件**。固定テンプレートの穴埋め
- `client/src/pages/cocreo/CocreoConsulting.jsx:18` が `setTimeout(..., 3000)` で3秒間「**AIエージェントが分析中...**」「経営戦略コンサルタントが課題を構造化中...」「専門エージェントをアサイン中...」を順に表示。**実際には何も動いていない**
- `client/src/pages/cocreo/SubsidyGenerator.jsx:72` も同様
- LPはこれを「AIコンサル」「補助金申請書AIが**3分で自動生成**」として**無料相談の入口**に置いている
- 入力を変えても出力が同じため、発見は容易

### 対処

**本日中に、演出を削除するか、LPの導線から外す（最短は公開停止）。** その後の選択肢は2つ。

## 3. 【至急】セキュリティ（3件・すべてコードで検証済み）

### 3-1. 本番の認証がハードコード値で稼働している可能性が高い

```
server/src/routes/auth.js:7,13   process.env.APP_PASSWORD || 'Optima1234'
render.yaml                      → APP_PASSWORD の記載なし（ANTHROPIC_API_KEY 等はある）
```

Renderのダッシュボードで手動設定していない限り、**本番はフォールバック値で動作している**。かつ全ユーザーが同一トークンを共有する実装。この文字列は公開リポジトリに平文で存在するため、**URLを知っていれば誰でも認証を通過できる**。

```js
const PASSWORD = process.env.APP_PASSWORD;
if (!PASSWORD) throw new Error('APP_PASSWORD is required');  // フォールバック撤廃・起動失敗させる
```

比較は `crypto.timingSafeEqual` に。`render.yaml` に `- key: APP_PASSWORD / sync: false` を追加。**コードから消すだけでは不十分で、パスワード自体の変更が必須**（git履歴に残るため）。

### 3-2. `/api/family-sheet` が認証の前段にマウントされ、レート制限もない

```
server/src/index.js:36   app.use('/api/family-sheet', familySheetRoutes);   ← 認証より前
server/src/index.js:39   app.use('/api', (req, res, next) => { ...認証... });
```

12MB×4枚の画像を受けて Claude Vision に投げる。**未認証かつレート制限なしのため、第三者にAnthropicの課金を焼かれる。** 公開ツールとして意図的に未認証にしている設計だとしても、レート制限は必要。`express-rate-limit` でIP毎10req/hour（0.2人日）。

### 3-3. SQLiteのWALファイルがgitに追跡されている

```
git ls-files  →  server/data.db-wal, server/data.db-shm
.gitignore    →  *.db （.db-wal / .db-shm にマッチしない）
```

現在のWALに顧客の個人情報は検出されなかったが、**同じ雛形で顧客案件を進めれば確実に漏れる**。`.gitignore` に `*.db-wal` `*.db-shm` `*.db-journal` を追加し `git rm --cached` を実行。

### 3-4. `render.yaml` のディスク未定義は「あえて直さない」

永続化すると、バックアップ・削除証明・暗号化の義務が発生する。**顧客データを置かない以上、揮発性のままが正しい。** `server/src/database.js` の冒頭に「このDBは揮発性。顧客データを置かないこと」を明記し、消失を許容する設計に倒す。**これが1人事業者にとって最も安いコンプラ対応。**

## 4. 唯一かつ最大の勝ち筋：「顧客データを預からない」

買い手3名が完全に一致した唯一の論点。**これは制約ではなく最大の営業文句。**

> **A**「実データは見せない。NDAでは足りない。外部の個人にCSVを渡した事実が監査で出たら、私が謝りに行く。**『私はデータに触りません』を最初に言い切ってくれた方が、むしろ信用が上がる**」

> **D**「**むしろ『触らない前提』で設計できる業者の方を評価します。** データに触らなくても7割はできると思っている。実データの汚れは当社の担当者がテスト実行して不具合を返す共同作業にすればいい」

> **E**「代理店が監査で『外部業者にデータは渡していません』と答えられる形なら、私は何も指摘しません。**それを設計思想として掲げている業者を評価します**」

### 文言（そのまま使う）

「お客様の責任です」と書くと丸投げに読まれる。以下なら3名とも「安心」と受け取り、**Dは稟議に貼れる**と述べた。

> **操作と実行は御社内で完結する設計です。当社は仕組みだけをお渡しし、データには一切触れません。**

### 実装：この設計は既に存在する

`client/src/features/family-sheet/` が完成品。localStorage完結（`useSheetStore.js`）、ブラウザ内OCR（`ocrClient.js`）、ファイル手渡し（`Handoff.jsx`）。**新規開発ではなく、この構造をコピーする。**

### データ授受の方式：撤回と確定

デリバリー担当の1周目案「実データ3行を氏名`テスト太郎`・証券番号下4桁`9999`に置換して渡す」は**撤回された**。理由は2つ。①外部の個人に業務ファイルを渡した事実そのものが監査で問われる ②マスキングの十分性を提供者が保証できない（証券番号の上位桁＋保険会社名＋満期日の組合せで特定可能）。Dの整理では**これは委託先審査に掛かる**（通せるが2週間かかる）。

**確定案：合成データ生成器を提供者が先に納品する。**

1. 「列定義シート（顧客が記入）→ その書式のダミーCSVを1000行吐く」ツールを渡す。Excel or ブラウザ完結、**工数1.5人日、全案件で使い回し可**
2. 顧客の担当者が実データを見ながら**設定だけ**を選ぶ（全角混在ON／姓名スペースあり／証券番号ハイフンあり／空欄率）
3. 生成されたダミーCSVだけが提供者に返る。**実データ由来でないので委託先審査の対象外**

Dが最も軽いと評価したのは「**当社内でテストして、不具合の内容だけをテキストで返す共同作業**」（データが1バイトも出ない、審査不要、Dの一存で即日）。合成データ生成器と組み合わせて第一案とする。

### 要件定義は共同テストで閉じるか

- **閉じるもの：表記ゆれ。** 往復のログを「値を出さない」設計（型・桁数・文字種・出現位置だけ返す）にすれば実データが渡らない。`ocrClient.js:toHalf()`（全角→半角、`，`、`－―ー‐` の正規化）を汎用の入力前処理として全経路に噛ませれば、**往復の半分は発生前に消える**
- **閉じないもの：業務例外**（分割計上・按分・キー欠損）。担当者は「エラーになった」とは返せるが「このケースはこう扱う」は返してこない。**日常業務として無意識にやっているため、自由記述で聞いても出てこない**
- **足りない道具：例外の言語化UI。** エラー行に対して担当者が**選択肢から**扱いを選ぶ画面が必要。`family-sheet/steps/PolicyEditor.jsx` の「AIの読み取りを人が確認・修正する」パターンを転用できる。**これを作らずに共同テストに入ると往復が発散する**
- **往復の実測見積もり：4〜6往復、提供者側3〜4人日、カレンダー時間3〜4週間**

### A層の扱い

> **A**「うちのIT予算は年間数十万。**うちは客じゃない**とはっきり申し上げます」

**A層は顧客ではなく、事例と口コミの供給源として扱う。** 標準テンプレの買い切り（数万円）で接点を持つ。個別要件定義をした瞬間に3人日では終わらないため、縮小版の受託はしない。

### (b) 監査・体制整備パッケージ：入口商材から除外

事業モデル担当が1周目に本命としたが、**全面撤回**された。

- **A**「年1回、私が3日徹夜すれば終わる仕事。**10万でも渋る**」
- **D**「35万なら体裁づくり分で採算は合うが、**体制整備の内部資料は満期データ以上に機微**。買うのは信用が確立した2年目以降」
- **E**「体制整備の点検は**代理店自身がやることに意味がある**。外注して体裁だけ整った資料は、**監査で最も嫌われるパターン**で実際に見抜かれる。売るなら『代わりに作る』ではなく『**代理店自身が作れるようにする道具**』と言うこと」
- デリバリー「本体は台帳の電子化であり、**Dが「絶対に外注しない業務」に挙げた募集人管理・教育記録に真正面から抵触**する」

### (c) 不備返戻チェック：再設計により全員が「設計としては合格」

1周目に買い手Dが最も高く買う（200万）と言い、2周目に3名全員が撤回（Dはゼロ円）、デリバリーの再設計を経て復活した経緯を持つ。

**再設計の3点**

1. **納品物の中でAIを動かさない。** AIは要件定義段階のみ（過去の返戻実績からルール表の初稿を起こす）。納品されるのは決定論的なルールエンジンとルール表
2. **ルール表は顧客が編集する。** 保険会社が基準を変えたら顧客の事務担当が行を足す。提供者は年1回の点検のみ（別契約）
3. **合否を出さない。** 出力は「要確認◯件」のリストのみで、「**不備なし**」を一切表示しない

この作法は新規発明ではない。`family-sheet/prompt.js` の EXTRACT_PROMPT ルール5「保険の良し悪しの評価、見直しの提案、他商品との比較は絶対に出力しない」、`schema.js` の「金額・日付は文字列で保持（計算しない＝業法対策の記録専用）」——**この開発者は既に「評価を出さない」設計を書けている。**

> **D**「**(3)が決定打**。私が拒否した本質は、『不備なし』が出た瞬間に**当社が機械の判断に依拠した**ことになり、募集ミス時に『システムが不備なしと言ったので』としか説明できなくなる点だった。要確認しか出さないなら、**当社の事務担当の確認義務は一切減っていない**。監査で説明できる」

> **D**「ルール表を当社が持つのは**加点**。1周目から気にしていた**バス係数の問題が構造的に消える**。提供者が倒れてもルール表は当社が動かせる。これは『負担の押し付け』ではなく『**主権の返還**』」

> **E**「2周目の『やめろと言う』は**撤回**。弊社が恐れていたのは『機械が不備なしと言ったので提出しました』という代理店が出ることで、その表示が存在しないなら指摘対象ではない。**ルール表を代理店自身が持つのは、むしろ弊社が推奨したい形**」

**ただし価格は200万→100万に下がる。**

> **D**「200万に戻さない理由は、**この道具は当社の事務チェックを置き換えず、上に一枚乗るだけ**だから。人が減らない投資に200万は出せない。**100万＝約1.5人月分の事務工数の削減見合い**が上限」

**契約に必須の2条件**

1. **ルール表の書式仕様書の納品**（これがないとバス係数の解消が形だけになり、結局その人にしか触れない）
2. **導入後3か月の従来チェック並走運用を標準手順として同梱**。Eが監査で見るのは「**盲信していない証跡**」であり、並走記録がある代理店には何も言わない

**残る既知のリスク（対処済みとはいえ消えない）**：A・D・E全員が「**要確認に挙がらなかった＝不備なし、と現場は受け取る**」と述べている。免責表示を出しても3か月使えば全員そう扱う。Aの評価は「**それでも構わない。今はベテラン1人の目視が合否になっていて、その人が見落とせば通る。機械が同じ精度で見落とすなら、リスクは増えていない**」。Dの対処は上記の並走運用。

### (d) 保険会社5社の自己点検シート様式の1本化 — 最有力の新候補

Dが2周目に自ら挙げ、Eが裏付けた。**本検証で最も筋の良い候補。**

> **D**「保険会社5社から来る『品質評価の自己点検シート』の様式がバラバラで、**同じことを5回書いている**。これを1本に統合する話なら、私は聞きます。**上限150万。(a)より先に買います**」

> **E**「その相談は**毎週来ます**が、弊社は他社の様式に触れられないので答えられません。日本代協は総論、hokanは自社機能の範囲、会計事務所は無関係。**誰も埋めていない穴です**」

優位性が重なっている。

- **Dの決裁枠内で完結、保険会社への照会が不要**と整理できる可能性が高く、**最速で契約できる**
- **「絶対に外注しない業務」に抵触しない。** Dの整理では、外注しないのは募集人管理・教育記録の「**中身の判断と責任**」であって、**同じ内容を5つの様式に転記する作業は単なる事務**。判断ゼロ、転記のみ

## 7. Claude Codeの実力：LP文言の判定

デリバリー担当の実測評価。**短縮率は実装フェーズで50〜70%、要件定義10%、テスト20%、納品・教育0%。プロジェクト全体で25〜35%。**「10分の1」は成立しない。工数は要件定義とテストに偏在しており、そこはAIで縮まない。

| 文言 | 判定 |
|---|---|
| 従来のSIerの**1/5の価格** | デリバリー「残せる」／競合アナリスト「撤回すべき」→ **実績ゼロでの根拠なき優位性表示はDに景表法リスク、Eの広告審査不通過、Aに『1/5の保険料と同じ胡散臭さ』と評価されたため、撤回する** |

| **最短2週間** | **書き換え必須**（共同テストの往復だけで3〜4週間） |
| **受託開発30万円〜** | **撤回**（13人日案件で日単価2.3万円＝赤字ラインを自ら公示している） |

Dが「共同作業にすればいい」と言っている以上、**往復を工程として明示する方が信用が上がる。短さを売るのをやめる。**

### 月額25万円の教育商材と何が違うか

**コード生成の速さでは差がつかない。差がつくのは要件定義の質だけ。**

顧客が自力で作ったものは動く。そして例外で壊れる。理由は§4と同じで、担当者が無意識にやっている業務例外は担当者自身がAIに伝えられない。**AIは聞かれたことに答えるので、聞き漏らした例外はコードに現れない。**

保険実務20年の提供者が「**それ、分割計上のときどう処理してます?**」と**先に聞ける**ことが唯一の技術的優位であり、価格の根拠はここにしかない。

**→ 訴求を「Claude Codeで速く作る」から「保険実務20年が要件定義をやる」に書き換える。** 前者は教育商材に負ける。後者は教育商材には絶対にできない。
