## 0. エグゼクティブサマリー

損保協会「自己点検チェックの取組み」は2026年度から業界共通シートの利用が必須となり、点検が毎年6〜9月（提出推奨期限9月末）に全代理店へ発生する。現場の作業負担は延べ20〜30時間。

**コンセプト:**

> **回答の正しさではなく、証跡の実在性で語れる状態をつくる。**
> 転記をゼロにし、「課題なし」と言い切る項目にだけ証跡を求め、
> 実態のない点検が代理店自身の画面で自壊するようにする。

**進め方**: 今季はフル機能を出さない。**①募集人点検ツール（Track A・8月中旬）**と**②有料の人力レビュー（Concierge）**を先に走らせ、実データと収益を得る。**③代理店用Excelラウンドトリップ（Track B）は、今季ベータを中止し2026年11月〜2027年2月へ移す**（提出直前に初公開する下振れリスクが上振れを大きく上回るため）。

### 1.3 2026年度版のシート構成（手引きP.15）

```
①留意事項シート  ②基礎情報入力シート  ③一覧シート
④回答シート（一般代理店用）／（自賠責のみ代理店用）  ⑤法令等遵守責任者入力シート
```

**①留意事項シートと、回答シートの2種化は2025年度版に存在しない。** §1.5の実測は2025年度版のものであり、そのまま2026年度版に当てはまらない。

**留意事項シートは「各留意事項に関する選択欄で『確認済』を選択」する構造**（手引きP.16）で、留意事項の中身は「個人情報を記載しないこと」「**改変してはいけないこと**」そのもの。→ **§5.1のホワイトリスト強制の対象。**

### 1.4 個人情報の共同利用条項（手引きP.15）— 設計を決定づける一次事実

> **１．個人情報等の取扱いについて**
> 損保協会、損保会社（代理店業務品質評価制度を利用しない会社を除きます。）、金融庁・財務局等では、自己点検チェックシートにおいて取得する代理店および代理店の従業者に関する個人情報について、**共同利用**しています。
> **個人情報（「基礎情報入力シート」で回答する各種責任者・管理者を除きます。）や機密情報は記載しないでください。**
> **共同利用者以外**（代理店業務品質評価制度を利用しない会社等）に自己点検チェックシートを**提供する場合**、個人情報保護法に沿って**本人同意の取得等の対応が必要**と考えられることに留意してください。

**cocreoは共同利用者ではない。** したがって公式Excelをサーバで受け取れば、代理店は法令等遵守責任者300名超から個別同意を取るか、cocreoを委託先として委託先監督（法25条・施行規則227条の9・金融分野GL）を果たす必要が生じる。**そしてその委託先監督の実施状況は、自己点検の点検項目そのもの**（個人情報管理／個人情報保護に係るシステム面の整備）である。

> **サーバ送信型は、自己点検支援ツールが自己点検の減点要因を作り出すという自己矛盾を起こす。**
> ブラウザ内完結により、この論点は「クリアする」のではなく**発生しない**。規約・説明資料では「クラウド例外に該当します」ではなく「**当社は当該個人データを取り扱いません**」と書く（前者は解釈に依存し、後者は事実）。

### 1.5 公式Excelの内部構造（**2025年度版で実測**・G1/G2で要再検証）

```
2025年度版シート構成: 基礎情報入力シート / 一覧シート / 回答シート
                      回答シート_値(hidden) / CSV出力シート(hidden) / 図(hidden)
```

- 5択回答は**フォームコントロール（ラジオボタン）922個**、`fmlaLink`先が`回答シート_値!D3:D173`
- **隠し`CSV出力シート`（578行）にキー→セルの正準マッピングが数式として格納**（うち499件が回答シート系への参照）

```
2025-001_設問①                            =回答シート_値!D3
2025-001_対象外選択理由                     =回答シート!AG10
2025-001_日常業務における取組み・好取組事例   =回答シート!AG12
```

この構造により、ツールは利用者のファイル自身から全フィールドのセル位置を導出できる（マッピングのハードコードが不要）。

**書き戻しの安全性（実測）:**

| 方式 | zipエントリ | ラジオボタン | 判定 |
|---|---|---|---|
| 元ファイル | 965 | 922 | — |
| **外科的zipパッチ** | **965（欠落ゼロ）** | **922（全保持）** | 変更は1エントリのみ。**964がバイト単位で同一** |

> **再現手順**: `python3 docs/selfcheck-xlsx-verify.py /tmp/selfcheck-verify`（協会ファイルは再配布しないため実行時に取得する）
> **ただしこれは2025年度版の検証である。** 2026年度版での再実行がG1/G2。

### 2.1 モートの正直な評価

**Excel書き戻しは「モート」ではなく「2〜4年のリードタイム」である。** 手法は出力ファイルを1つ入手して元ファイルとdiffすれば露見し、資金のある競合なら2週間で追随できる。そして毎年テンプレートが改訂され指紋照合が不一致になるため、**堀は積み上がらず毎年更地から作り直す**。さらに、殺しに来る相手（協会のWeb化、hokan、保険会社の記入要領）を1つも止めない。

**Track Aもモートではない。** 協会が推奨したGoogleフォームとの差分は「70設問の投入を代行する（一度きり2〜3時間の節約）」「未提出者一覧」程度で、しかも**データの置き場所が自社Googleアカウントからcocreoのサーバに移る**という信頼上の逆風がある。→ **無料で正しい。有料化の対象にしない。**

**唯一「時間とともに強くなるもの」は、自店の縦の履歴である。**

前年回答・証跡鮮度の推移・改善完了率・**保険会社から受けたフィードバックの蓄積**。これらは他店との比較ではないため禁止8に当たらず、制度趣旨（PDCA）に正面から合致し、2年目に「去年の履歴が全部ここにある」という切替コストを生む。**設計書はこれをモートとして扱う**（§5.3 B9・§5.5）。

## 4. コンセプト

### 4.1 柱の根拠

v1.0の「正直に書く勇気」は**手数料ポイント連動と正面衝突していた**。損保ジャパンは2026年7月から挙績・増収率ポイントを廃止し、大手各社が規模の比重を下げて品質評価に振っている。代理店にとって正直に書くことは短期的に損をしうる選択であり、そこに説教しても動かない。

ツールが動かせるのは**証跡の側**である。ただし全項目に証跡を求めれば負担増で使われない（→§5.3 B3の非対称設計）。

### 4.2 価値提案

1. **転記がゼロになる**（Track B・2027年〜）— 公式Excelを読み込み、ガイド付きで回答し、入力欄だけを非破壊で書き戻す
2. **「課題なし」と言うときだけ証跡を求める** — Aと答えるなら裏付けを出せて当然。Bと認めるなら求めない。**この非対称性が「正直に書く方がラク」という誘引を作る**
3. **公式Excelファイルは端末から出ない** — 解析・パッチは100%ブラウザ内。§1.4により、これは訴求である前に必然

> **訴求の正確化（必須）**: 「ファイルはPCから出ません」だけを書いてはならない。**回答データはサーバに保存され、AI推敲を使えば記述テキストは送信される。** 同じ画面に並べて書くこと。
> 「**公式Excelファイルは送信されません。回答データは改善提案のためにお預かりします。記述欄の推敲支援をご利用の場合、当該テキストのみが送信されます（既定はオフ）。**」

### 4.3 名称と誤認防止

**「自己点検ナビ by Cocreo」**。「公式」「認定」「協会」を名称に含めない。iOSアプリの「業務改善チェック」とは呼び分ける。

全画面フッターに常時:
> 本ツールは、一般社団法人日本損害保険協会が公表する「自己点検チェックシート」への対応を支援する非公式の民間ツールです。同協会および保険会社とは関係ありません。提出は所属保険会社の案内に従い、登録プラットフォームから行ってください。個別の法的判断は弁護士または所属保険会社にご確認ください。

**「協会に照会済み」「確認済み」は対外表示しない**（「協会公認」と読まれる）。照会の事実・回答のいずれも、社内保管と保険会社への事前説明の場での提示に留める。

## 5. 機能設計

### 5.1 Track B の中核機構: クライアントサイド Excel ラウンドトリップ

> 利用者が登録PFから取得した公式Excelをブラウザで**読み込み** → `CSV出力シート`から構造を自己解析 → ガイド付きUIで**本人が**回答 → 入力欄のみを外科的にパッチした新ファイルを保存 → **本人がExcelで確認して**登録PFへ提出

**法的根拠の整理（v2.0から差し替え）**
- **手引きP.15への適合**は「レイアウト・書式・数式等を改変しない」ことであり、964/965のバイト同一性がこれを機械的に証明する
- **著作権法上の正当化はバイト同一性ではなく、クライアント完結により事業者が複製の主体にならないことである。** サーバ処理なら事業者が複製主体と評価される余地（カラオケ法理・ロクラクII型の「枢要な行為」論）が生じる。入力欄への記入は著作物の改変ではなく予定された利用態様であり、仮に改変と構成しても著作権法20条2項4号の範囲

**ホワイトリスト強制（最重要・v2.0に欠落していた事故要因）**

2026年度版で新設された**留意事項シートは「確認済」を選択する構造**であり、その中身は「個人情報を記載しないこと」「**改変してはいけないこと**」そのものである。

> **ここをツールが自動入力すれば、「改変禁止を読んで確認した」という表明を、本人が読まないまま代わりに立てることになる。** 書き戻し機能全体の正当性を内側から破壊する、最も事故になる1セルである。

実装は「除外する」ではなく**ホワイトリストで強制**する:
- `CSV出力シート`から導出したキーのうち、**`回答シート` 系セルを参照するものだけ**を書き込み許可対象とし、他シートへの書き込みはコードレベルで到達不能にする
- **留意事項シート・基礎情報入力シート・法令等遵守責任者入力シートは書き戻し対象外**（氏名等を扱うため）。画面はコピーボタン方式に留める
- 差分アサートの粒度を「対象シートXMLのみ」から**「許可済みセルアドレス集合のみ」**へ上げる

**提出事故防止ガード**
- **テンプレート指紋**が検証済みリストと一致しなければ書き戻しを拒否し、コピーボタン方式へフォールバック
- **【追加】ラウンドトリップ照合**: 書き戻し後のファイルを**自ツールで再パースし、UI上の回答と全フィールドが一致することを検証**する。差分アサートが保証するのは「壊していない」ことだけで、**マッピングが1行ずれれば、アサートを100%通過したまま171問すべてが隣の設問に書き込まれる**（最も発見が遅れる壊れ方）
- **変更箇所一覧の出力**（「2026-012 設問②に『B』、確認資料欄に『個人情報取扱規程』を書き込みました」を全件）。利用者が突き合わせるため
- 元ファイルは上書きしない（`_入力済`サフィックス）。**ファイル名に「Excelで開いてください」を含める**
- **実機確認結果をヘルプに常時掲載**（「Excel 2021 / Microsoft 365 で開き、ラジオボタンの選択と一覧シートの集計が一致することを確認済み。確認日◯月◯日、バージョン◯」）。これは社内工程ではなく**ユーザーの最大の関心事**
- ダウンロード前の必須チェックボックス（責任所在の確認まで格上げ）:
  > □ 出力ファイルを **Microsoft Excel** で開き、回答内容と表示に問題がないことを自分で確認したうえで登録PFへ提出します。記載内容が当店の業務実態と合致していることについて、当店が責任を負うことを理解しました。

**UI文言（現場からの指摘）**
- **「アップロード」の語を使わない。**「ファイルを読み込む（送信されません）」とする。「アップロード」と書かれていれば非技術者は中身が送られると考え、説明では覆らない
- **「Wi-Fiを切ってもこの画面は動きます。お試しください」と画面に書き、実際に動く。** 非技術者にとってこれが唯一の証明であり、説明資料10ページより強い

**B3 証跡入力の非対称設計（v2.0の全項目必須から変更）**

v2.0案（46大問×4属性＝184フィールドを必須）は、**転記を消した分より多い入力を要求する**構図であり、現場判定は「使わない」だった。特に「直近12か月の実績」は、記録がないから点検で困っている代理店には答えられず、**空欄か適当な数字**を招く。

| 自己評価 | 求める証跡入力 |
|---|---|
| **A（取り組んでおり課題はない）** | **4属性すべて必須。** 課題なしと言い切る以上、裏付けを出せて当然 |
| B（取り組んでいるが課題がある） | ①文書名のみ必須。②③④は任意 |
| C（取り組んでいない） | 入力不要（無いものの更新日は書けない） |
| D / E | 入力不要 |

**この設計は「4属性を埋めたくないなら、正直にBと書けばいい」という逃げ道を正しい方向に開く。** 全項目必須は逆に「面倒だから全部Aにして適当に埋める」を誘発する。証跡で語らせたいのは「課題なしと主張している項目」であって、既に課題ありと認めている項目ではない。

実装上の必須事項:
- **③責任者はプルダウン**（一度登録した社内メンバーから選ぶ）。46回も氏名を打たせない
- **④実績は入力欄でなく選択式**: 「実施した（回数は任意）／実施していない／**記録がなく分からない**」。**「記録がなく分からない」の選択肢を必ず用意する。** 数字を書かせようとすると書けない人は嘘を書く。選ばせれば正直が一番ラクになり、**「記録がなく分からない」が並んだ画面こそが見せたかったものになる**
- **文書マスタ**: 「個人情報取扱規程」は5〜6の大問で使い回す。一度登録した文書を選べるようにする（入力量が半分以下になる）

**進捗指標（v2.0から変更）**

v2.0は主指標を「証跡が1年以内に更新されている項目%」に置き換えたが、**締切がある作業で「あと何問残っているか」が分からない画面は使われない**。また証跡率だけの画面は「人に見られたくない」という反応を生み、§6.2の保険会社共有導線の前提も崩れる。

→ **主指標は「回答完了率」、その真下に同じ大きさで「証跡が1年以内に更新されている項目率」を併記し、両方を消さない。** 「回答は98%なのに証跡は31%」という**並び**こそが自壊であり、片方を消す必要はない。低い場合のメッセージは説教口調にしない（「31%です。危険です」ではなく「31%です。まず更新日が古い上位3件から手を付けると効率的です」）。

### 5.4 制度上の空白を埋める（最大の機会領域）

協会は「レベル感は一律に設けることは合理的ではない」と公言しており、**ここは公式では永久に埋まらない**。現場の残る問いは「何を用意するか」ではなく「**うちのこれで足りるのか**」である。公式の確認資料例は「社内規程」「研修実施記録」と示すが、10年前の雛形で足りるのか、朝礼15分は研修か、を教えない。

**(1) 「よくある実態 → 足りている／足りていない」対応表**（20〜30項目でも効果が大きい）
> 例: 「規程が雛形のまま5年以上更新なし → 足りていません。最低限、責任者名と実態に合わない条文の2点だけでも直せば形になります」

**(2) 改善アクションは「整備してください」で終わらせない。**「整備が必要です」と言われて何も渡されないレポートは閉じられて終わる。→ **個人情報取扱規程と教育記録の様式の2つだけは今季に付ける**（B/C判定になる代理店が圧倒的に多い）。規程ひな形と改善アクションは切り離すと両方死ぬ。

**(3) 「対象外」判断の構成ガイド（v2.0が完全に見落としていた論点）**
現場で最も怖いのは5択の選び方ではなく「**うちみたいな小規模代理店にこの項目は適用されるのか**」である。BCP、利益相反管理、システム面の整備——役員2名・募集人5名の会社にどこまで求められるか分からず、安易に対象外にして後で保険会社に理由を問われるのが最悪のシナリオ。協会が「レベル感は示さない」と公言している以上、ここが最大の空白。

**ツールが「これが正解です」と言うのは禁止4に触れるが、「対象外にする場合、理由欄に何を書けば説明になるか」の構成ガイドは作れる。記述式5項目より需要が大きい可能性がある。**

### 5.5 乗合代理店への対応（v2.0が外していた本丸）

業界共通シートを登録PFで提出すれば全所属保険会社への提出は一度で完了するが、**各損保会社が独自に作成・提供するシートは残る**。5社乗合なら共通1本＋各社独自が上乗せされ、**乗合代理店にとってはここが二度手間の本丸**である。v2.0は「共通シート1本」を前提に全体を組み立てていた。

さらに、乗合の最大のペインは「A社は問題ないと言い、B社は不十分と言う。どちらに合わせればいいか誰も教えてくれない」であり、**協会は「一律の要件や目安を設ける予定はない」と回答している**。

**v2.0の禁止10（保険会社別の運用差分情報の提供禁止）は、このペインを丸ごと封印していた。** 線を引き直す（§5.6 の10を参照）:

- **他代理店への情報提供・公表は禁止のまま**
- **自店が受けたフィードバックを、自店のために記録・比較する箱は解禁する。** 公式シートには「前回以降の保険会社からのフィードバック等」欄が**大問ごとに存在**し、現状は毎年ゼロから思い出して書いている。社ごとに記録し翌年この欄へ引き継げるだけで、乗合代理店にとって他と別物になる
- これは§2.1の「時間とともに強くなるもの」＝唯一のモート候補と同一の機能である

> 本サービスは、**記入代行ではありません。** ご記入いただくのは貴店です。当社が行うのは、点検項目の趣旨の解説、証跡の棚卸し、記述の構成についての助言、および未整備事項の整理です。回答の選択と記述内容の決定は、貴店の業務実態に基づき貴店が行っていただきます。これは制度上の制約であると同時に、**貴店の点検が「実施された」と評価されるための要件**です。

最後の一文により、**制約を制約として売る**ことで、営業現場が代行に滑る圧力そのものを弱める。Conciergeの作業定義書（何をやり何をやらないか）を先に作り、担当者が例外を作れない形にする。

### 5.7 Track A と Track B の接続（両レビュアーが独立に指摘）

v2.0の画面フローはTrack AとTrack Bが並列に分岐して**繋がっていなかった**。このままではTrack Aのユーザーは募集人点検だけ済ませてTrack Bへ戻ってこない。

> **Track Aの出力は、そのままTrack Bの証跡になる。**
> 募集人点検を実施したという事実・集計結果・**面談記録（A5）**は、代理店用シートの募集管理・教育に関する大問の確認資料そのものである。

Track Aの完了画面が「代理店用シートの◯番の確認資料が1つ埋まりました」と言えれば、**Track BへのブリッジとConciergeへの導線が同時に立つ**。これは「便利な連携」ではなく、**2つのトラックを1つのプロダクトにする唯一の必然性**である。

## 6. ビジネスモデルと関係構築

### 6.1 ファネル

```
Track A（無料）・SEO記事 ──→ メール登録（BtoBリード）
                                   │
        ┌──────────────────────────┴─────────────────┐
        ▼                                             ▼
[Concierge: 自己点検レビュー **3社 × 25万円**]   [Track B（無料〜低額・2027年〜）]
  人力・成果物が残る・2往復・来年自走                       │
        └──────────────────┬──────────────────────────┘
                           ▼
                [伴走サービス（初期30〜80万円＋月額）]
```

**Concierge の設計（v2.0の10万円×5社から変更）**

- **価格 25万円**: 原価は1社2〜3人日＝10〜15万円で、10万円は赤字。かつ「171設問を見て10万円」は設問あたり585円で、**安すぎることが品質シグナルとして逆に働く**。買い手は「無料で済ませたい層」ではなく「不安だから金を払う層」。10万→伴走30万は3倍のジャンプだが、25万なら1.5〜4倍で心理的連続性がある
- **社数 3社**: 5社×2.5人日＝12.5人日は、8月中旬〜9月中旬に1.5FTEの42%を占め成立しない。学習目的では3社と5社の情報量の差は限界的。**3社×25万＝75万円は5社×10万＝50万円を上回り、原価も7.5人日に収まる**
- **成果物3点をファイルで渡す**（①不備項目一覧 ②不足している規程・記録のリスト ③9月末までの改善スケジュール表）。**保険会社との対話にそのまま持っていける中立的な体裁で。** 「コメントするだけ」なら現場評価は5万円が上限（コメントは消えるため）
- **記述式5項目は「レビュー」ではなく「同行」**。画面を見ながら一緒に埋める。他人にコメントされても書けるようにはならない
- **2往復必須**（事前レビュー→90分会議→修正後の再確認）。1回きりなら5万円の価値
- **「来年は自分でできるようになる」ことを約束する。** 毎年10万円なら買わない
- **「5社限定」という表現は使わない。** 地方の代理店主は「限定」を見ると「どうせ埋まっている」と考えて問い合わせない。「今季は初回のため、じっくり伴走できる社数に絞っています」とする
- **商品の定義を変える**: 8月中旬開始で9月末提出まで1か月半しかなく「規程を作りましょう」では間に合わない。**「今年出すシートを仕上げる」ではなく「今年は正直に課題ありで出し、来年6月までに整える計画を作る」商品**とする方が誠実であり、現場の信用も得やすい
- **売り方**: Web経由で9月末までに3社は不可能。**cocreoの既存接点リストへの直接アプローチが唯一確実**（→G5）。次点で代協支部への無償登壇。**保険会社への事前説明の場で営業してはならない**（§6.2の目的そのものを損なう）

### 6.2 保険会社との関係構築

保険会社が敵に回った瞬間にプロダクトは死ぬ。そして先に説明に行くかどうかで扱いが変わる。ただし**両刃**である: 説明に行けばまだ誰も知らない構想を規制側に最も近い立場へ自ら周知することになり、**明示的にNGと言われれば、それを知りながら出すことになり悪意が推定される**。

→ **順序を固定する: 中小損保・共済・少額短期1社 → 反応を見て設計調整 → 大手。** 逆順は取り返しがつかない。彼らは指導リソースがより薄く、協業の現実的な入口でもある。

到達目標は「黙認」ではなく「補完としての推奨」。条件は、①未整備項目レポートを**代理店自身の意思で**共有できるエクスポート（**事業者から直接送るのは絶対に不可**）、②実装禁止リストの規約レベルでの公開、③セキュリティ説明資料、④「合格」示唆表示が一切ないこと。

**【規約に明記】cocreoは、保険会社・協会・第三者に対し、回答データだけでなく「本ツールを利用している代理店の名称」も共有しない。** これが無いと登録の段階で止まる代理店がいる。

### 6.3 iOSアプリ「業務改善チェック」との役割分担

アプリ＝日常の簡易セルフチェック（気づきの入口・完全無料）／本ツール＝年1回の本番作成支援。相互導線を張る。

## 7. データ・プライバシー設計

1. **公式Excelの解析・パッチは100%ブラウザ内**。ファイルは一度もサーバに送信されない（§1.4により必然）。規約は「クラウド例外に該当」ではなく「**当社は当該個人データを取り扱いません**」と書く
2. サーバが持つのは項目コードをキーとした回答データとメールアドレス、およびTrack Aの募集人回答
3. **【G4】募集人回答データの保管リージョンを国内に確定する。** 国外なら「外国にある第三者への提供」（法28条）に該当し、募集人1名ごとの同意取得が必要になって実質的に成立しない。`render.yaml` のリージョン設定を実装前に確認
4. **代理店との間で個人データの取扱いに関する委託契約（法25条）を締結**（利用規約への組み込みで足りる）。法23条の安全管理措置を実装し**説明資料として文書化**する（これは代理店の点検項目の証跡としてそのまま使えるため営業上も価値がある）
5. **AI推敲は明示的オプトイン（既定オフ）＋送信前のPII検知を必須ブロックゲート**（警告のみでは不十分）。検知対象は個人名・募集人ID・契約番号・機微情報。手引きP.15が「個人情報や機密情報は記載しないでください」と明記している以上、これは記述欄UIに常時表示すべき制度上の要求でもある
6. **保険会社・協会・第三者への共有は事業者からは一切行わない**（利用代理店名を含む）。代理店自身が出力して提示する導線は塞がない。**中立版レポートは氏名・募集人IDを機械的に排除**
7. **証跡ファイルの保管棚は作らない** — 登録PFに確認資料の提出機能がなく必然性が低い一方、預かれば漏洩責任だけが残る。4属性のメタデータのみ持つ。将来提供する場合も一次保管は自社側に置く運用を推奨
8. トークンURL: `randomBytes(32)`、募集人1名=1トークン、有効期限（発行から45日）、提出後は編集ロック、レート制限とトークン列挙対策、`noindex`
9. 保持期間（最終ログインから24か月）と削除手順を規約に明記。**全データのエクスポート保証**
10. 未整備項目レポートは「当店はXについて未整備である」と自認する文書であり証拠になり得る。**サーバ側の保持を最小限にし、代理店が随時削除できることを規約に書く**
11. **cocreoは内部通報の受け皿にならない**旨を規約に明示

## 10. レビュアー間で衝突した論点の裁定

| 論点 | 対立 | 裁定 |
|---|---|---|
| **公式Excelへの書き戻し** | 法務「代行生成・改変はNG」 vs PM「手引きの実文言は入力欄への入力を許容」 | **書き戻しを採用**。ただし法務の再検証により**ホワイトリスト強制**（留意事項シートへの書き込み禁止）が条件。著作権上の根拠は「バイト同一性」ではなく**クライアント完結により事業者が複製主体にならないこと** |
| **匿名ベンチマーク** | 事業戦略「唯一のデータモート」 vs 保険会社「制度の私物化」 | **外部提示は禁止**（保険会社を採用）。ただし**識別されない統計の内部利用は可**（法務の書き分け）。モートは**自店の縦の履歴**に求める |
| **保険会社別の運用差分** | 保険会社「全面禁止」 vs 現場「乗合最大のペインであり、自社記録は封じるべきでない」 | **「他者への提供」は禁止、「自店が受けたフィードバックの自店内記録」は解禁**。法的な効き所は制度私物化ではなく**信用毀損**であり、この理由なら線は自然に「非公開・伝聞情報の禁止」に収まる |
| **証跡4属性** | 保険会社「全項目必須化」 vs 現場「184フィールドは負担増で使わない」 | **回答Aのときだけ必須**という非対称設計。「埋めたくないなら正直にBと書けばいい」という逃げ道が正しい方向に開く |
| **進捗の主指標** | 保険会社「証跡の実在・鮮度を主に」 vs 現場「締切作業で残数が見えない画面は使わない」 | **併記**。片方を消すとツールを開かなくなる。「回答98%・証跡31%」という**並び**が自壊であり、主従を変える必要はない |
| **今季リリース** | 事業戦略「Track Bの9月ベータはNO GO」 vs PM「32人日で可能」 | **Track Bを11月〜2月へ移す**。提出直前に初公開する下振れが上振れを上回り、かつ工数が成立しない |
| **募集人設問データ** | PM「協会が公開しているので原文を搭載可」 vs 法務「FAQの名宛人は代理店であり、第三者の事前搭載は態様が異なる」 | **利用者がdocxを読み込む方式**を既定に。§5.1と原理が統一される |

```
  xlsxZip.js        // fflate による zip 読み書き（バイト保存）
  mappingParser.js  // CSV出力シートの数式を解析 → {key: {sheet, cell}} を導出
  allowlist.js      // 回答シート系セルのみを書き込み許可（他は到達不能）
  sheetReader.js    // sharedStrings/inlineStr を解決して現在値を読む
  sheetPatcher.js   // 数値: <v>、文字列: t="inlineStr" で対象セルのみ置換（s= を保持）
  fingerprint.js    // テンプレート指紋の算出と検証済みリスト照合
  verifier.js       // 差分アサート（許可セル単位）＋ ラウンドトリップ照合
  docxParser.js     // 協会の募集人向け設問データ（docx）をブラウザ内でパース
```

- **ルート**: `/cocreo/selfcheck`（Track B）、`/cocreo/selfcheck/staff`（Track A）。既存の `/cocreo/subsidy-generator` と同パターン
- **サーバ**: `server/src/routes/selfcheck.js`（回答データ・トークンURL発行・集計）。**公式Excelファイル本体はサーバに送信しない**。**保管リージョンは国内**（G4）
- AI補助は既存 `claudeService`。**オプトイン・PII検知ブロック・出力は書き戻し経路から隔離**
- 既存スタック: React 18 + Vite + Tailwind + react-router（JSX、TypeScriptなし、**テスト基盤なし**）／ Express + better-sqlite3 + multer
- **検証ハーネスは実ファイル回帰テストが必須。ただし実ファイルには氏名が含まれるためリポジトリに置けない** → ダミー入力済みの空ファイルを別途管理する運用を先に決める

## 12. 意思決定ポイント（G1〜G5は§0.1のゲートへ格上げ済み）

1. **Concierge の価格25万円・3社という設計の採否**
2. **保険会社への事前説明を誰が行うか**（順序は中小・共済→大手で固定）
3. **検証用の2026年度版ファイルをどう調達するか** — 実代理店から借りる場合、**法令等遵守責任者の氏名・募集人IDが含まれるため書面の取扱合意なしに受領しない。ダミー入力済みの空ファイルを提供してもらう運用を推奨**
4. **協会照会に回答が得られない場合の分岐**（業界団体が個別事業者に回答しないことは珍しくない）→ §5.2 A1' を既定路線とする
5. **第三者評価機関との関係** — 協会は2025年7月に準備室名義の資料を公表済み。審級は保険会社・協会・評価機関の三つ
